# SoundAlert v0.2.0 — Automatic Reliable Alert

## Product rule

**One screen. One switch. One sensitivity control. Everything else automatic.**

The normal user sees only:

- a full-screen status/alert background;
- one large ON/OFF control;
- one sensitivity slider.

No scrolling, mode picker, confidence percentages, history, or technical controls are exposed in normal use.

## Automatic detection

Once the user presses ON, the microphone foreground service remains active. SoundAlert automatically biases its internal context between ROAD, HOME and UNCERTAIN using:

- on-device YAMNet audio context labels;
- low-rate accelerometer motion;
- continuously learned background scores.

This does **not** use GPS and does not save location.

Context only changes thresholds. It never completely disables horn or door detection, so a wrong context guess cannot fully blind the app to an important sound.

## Positive sound groups

### Road
- Vehicle horn, car horn, honking
- Toot
- Air horn, truck horn
- Bicycle bell

These cover the generic acoustic classes expected to include Indian car, motorcycle, auto-rickshaw, bus and truck horns. v0.2.0 does **not** claim vehicle-type identification; real Indian recordings are still required for later custom training.

### Emergency
- Emergency vehicle
- Police car siren
- Ambulance siren
- Fire engine/fire truck siren
- Siren

### Home
- Doorbell
- Ding-dong
- Knock

## Explicit negative/background filtering

The model output is actively suppressed when strong background classes dominate. The negative list includes the requested categories:

- speech/conversation/shouting/crowd;
- music/radio;
- engines/idling/revving;
- wind and microphone wind noise;
- construction: jackhammer, hammer, drill, power tools, sawing, sanding;
- traffic/roadway noise without horn;
- television;
- dogs/barking/howling/growling;
- household sounds: dishes, cutlery, chopping, frying, microwave, blender, water, vacuum, fan, air conditioning;
- generic environmental/noise classes.

## False-alert filtering

A single uncertain model frame does not alert. SoundAlert requires **2 of the most recent 3 frames** to agree on Horn, Door or Siren.

Strong background classes apply an additional score penalty unless the positive event is exceptionally strong.

## Reset after vibration

Immediately after an alert:

1. the multi-frame history is cleared;
2. new alerts are blocked until the vibration pattern completes;
3. the detector requires two quiet frames before it arms again.

This prevents one continuous horn or doorbell from repeatedly vibrating the phone without reset.

## Haptics

- Horn: LONG — short — LONG
- Door: short short — pause — short short
- Siren: triple-long — pause — triple-long

The Wear OS companion uses the same vocabulary.

## Flashlight

Flash alerts are disabled by default. A caregiver/user can long-press the large ON/OFF control for one second to toggle flash alerts. A small lightning symbol indicates that flash is enabled.

## Screen locked/background operation

SoundAlert uses an Android microphone foreground service and a partial CPU wake lock while ON. The user must start SoundAlert while its activity is visible because modern Android does not permit silently starting a microphone foreground service from the background.

After a reboot, if SoundAlert was previously ON, the app posts a small resume reminder rather than violating Android's microphone-start restrictions.

## Privacy

- No microphone recordings are saved.
- No audio is uploaded.
- Classification runs on-device.
- No GPS/location permission.
- Calibration stores only numerical background baselines.

## Size strategy

v0.2.0 removes Jetpack Compose and uses one custom Android View. CI fails if the phone debug APK exceeds 25 MiB; the design target is lower. The YAMNet mobile model itself is about 4.13 MB and is downloaded/verified during CI rather than stored in the source repository.
